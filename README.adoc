= Typell — Verification Kernel for Type-Safe Database Queries
:toc: preamble
:toc-title: Contents
:icons: font
:doctype: article

The type-theoretic verification engine providing best-of-breed type system coverage for formally verified database queries. Dependent, linear, session, quantitative, effect, and modal types in one stack.

== Overview

Typell is to PanLL what LLVM is to Clang: the compiler infrastructure that any frontend can consume. PanLL is the primary consumer (the full neurosymbolic development environment). VS Code extensions, CLI tools, and CI/CD pipelines are secondary consumers.

Typell validates queries. It does not store data. It provides proof-carrying code: cryptographic proof certificates attached to validated queries, ensuring connections close, resources are used exactly once, transactions are atomic, and rate limits are respected.

== What Typell is NOT

* **NOT a standalone IDE** — it is a verification engine consumed by tools.
* **NOT a database** — it validates queries, it does not execute them.
* **NOT a theorem prover** — it delegates complex proofs to external solvers (Echidna).

== Target type-safety coverage

[cols="1,2", options="header"]
|===
| Type system | What it enforces for queries

| Dependent types
| Schema constraints, arity matching, join key compatibility

| Linear types
| Resources used exactly once (no data leaks, no double-reads, connections closed)

| Session types
| Protocol safety (connections always closed, transactions atomic, handshake order)

| Quantitative Type Theory (QTT)
| Resource quantity tracking (rate limits, cost analysis, read quotas)

| Effect systems
| Explicit side effect tracking (read/write/memory, isolation guarantees)

| Modal types
| Contextual access control (transaction-scoped data, temporal validity)

| Proof-carrying code
| Cryptographic proof certificates attached to queries
|===

== Technology stack

[cols="1,2,2", options="header"]
|===
| Layer | Technology | Rationale

| Formal specs
| Idris 2 (`src/abi/`)
| Dependent types prove type system soundness. Zero `believe_me`.

| Kernel
| Rust (`src/kernel/`)
| Performance, safety, Tauri compatibility (PanLL backend).

| FFI
| Zig (`ffi/zig/`)
| C ABI compatibility per hyperpolymath universal standard.

| Protocol
| JSON-RPC
| Language-agnostic. Any consumer can talk to Typell.
|===

== Known scope boundaries

[CAUTION]
====
**Phase 0: Vision capture and repo scaffolding.** The architecture is designed; the implementation is beginning. The directory structure exists but the kernel, type checker, and proof engine are under active development.
====

[CAUTION]
====
**Complex proofs delegate to Echidna.** Typell is a verification kernel, not a theorem prover. Proofs exceeding Typell's automated capacity are dispatched to external solvers.
====

[CAUTION]
====
**Idris 2 ABI is the specification; Rust kernel is the implementation.** Soundness depends on the alignment between the Idris 2 formal specs and the Rust implementation. The FFI bridge (Zig) must maintain this alignment.
====

== Build

[source,bash]
----
# Idris 2 formal specs
cd src/abi/
idris2 --build Typell.ipkg

# Rust kernel
cd src/kernel/
cargo build

# Zig FFI
cd ffi/zig/
zig build
----
